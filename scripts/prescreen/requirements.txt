# Verification-only dependencies for the MEME hit-likelihood gate.
#
# These are NOT application dependencies and must never become one. THE GATE ships no ML runtime:
# the browser walks XGBoost's own save_model() JSON in about 40 lines of plain JS (xgbEnsemble.js
# over meme_gate.json), with no converter and no intermediate format between the file the ML team
# exports and the bytes the browser parses.
#
# (This file used to say "DM3 ships no ML runtime at all". That stopped being true when AxoMEME 2.0
# arrived — it is a 3.78 MB transformer and needs onnxruntime-web, which no hand-written walker is
# going to replace. The gate is the opposite case and stays runtime-free: three features, 500 trees,
# reachable from every method, so a runtime behind it would be paid for by all fifteen. The
# reachability guard in src/test/meme-hit-likelihood.test.js is what holds that line now.)
#
# xgboost is here for exactly one reason: to be an INDEPENDENT SECOND IMPLEMENTATION of that walk,
# reading the same bytes, so CI can prove the shipped JS reproduces the library's own scoring
# (scripts/prescreen/verify_parity.py). It must stay on this side of the fence. Nothing here reaches
# a user, and if it ever appears in package.json something has gone badly wrong.
#
# Keep this version in step with whatever the ML team exports from: the walker treats base_score as
# a PROBABILITY, which is the XGBoost >= 2 semantics, and a same-major change to that convention
# would be caught only by the parity run.
xgboost>=3.0
numpy>=1.26
