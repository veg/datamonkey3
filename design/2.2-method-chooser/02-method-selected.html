Why this shape

The question line is the whole fix for the vanishing hint. "Which sites are under selection?" sits above the chosen method for the rest of the session. It costs one 17 px line and it is the only thing on this screen that tells a returning user what they decided and on what basis. Nothing new is invented: it is the legend from state 01, kept.
Steady state is 14 px smaller than today. 81 px summary + 16 px margin = 97 px, against 111 px for the current select plus its description block. The 478 px spent in state 01 is not carried; it is borrowed for the length of the decision and repaid on the click that ends it.
"Change" reopens the chooser in place, with FEL still selected. It must not clear methodOptions. A user comparing FEL against FUBAR should be able to look and come back without losing a branch selection they spent five minutes tagging on a tree.
One documentation link, here, and nowhere else. methodConfig[method].url (+page.svelte:74–197) holds a hyphy.org slug for all sixteen methods and is read by nothing. Surface it once, on the method actually chosen, at the moment before committing. Fifteen links in the chooser would be the documentation layer this feature must not become. Mark it as leaving the app (↗) — it is an outbound link, and the local-serving constraint in CLAUDE.md is about fetched assets, not hyperlinks.
Do not add a runtime label to the chooser. RunOutlook (:1445–1456) already states expected runtime for this alignment, which a static "Slow" badge cannot. The audit says this and the audit is right.
The Beta badge moves with the method. If AxoMEME is the selection, the summary row reads "Which sites are under selection? · AxoMEME [Beta] · Predicts what MEME would report…" — the surrogate relationship is restated, not dropped, because that is exactly the claim a user is about to publish against.
