When the uploaded file cannot support a method

The audit proposes a per‑method codon‑alignment requirement line driven by CODON_AWARE_METHODS. I checked what that predicate is actually worth in this product, and it is worth nothing. Panel A is overruled. Panels B and C are the correct design.

Twelve of fifteen methods, all saying the same thing, about a condition that is true of every file the app can hold.

Why A is overruled

The app cannot hold a non‑codon alignment. datareader.bf:189 sets genCodeID = 0 and nothing overrides it — +page.svelte:886 runs the script with no arguments. So :255 rejects any alignment whose column count is not divisible by three, :238–244 rejects anything that is not four‑state, and :262 rejects an all‑stop‑codon file. Upload fails; the file never becomes current.
Therefore FILE_INFO.gencodeid is always 0. The −1/−2 branches are unreachable. Which also means the GARD datatype auto‑detect at MethodSelector.svelte:1082–1092 always resolves to 'codon' — a third dead path in this component, alongside the priority sort and browserOnly.
A predicate that never varies is not information. Twelve identical lines would cost twelve rows of attention to say something that is true by construction. Principle 10: this is not annotation, it is noise with a citation.
Do not sort unsupported methods into a trailing group either. The audit proposes that. It would move a method to a different place depending on the file, so FEL is in a different position on different days — and it blames the method for a problem that belongs to the file.

What B and C fix

B closes a real hole. +page.svelte:804 persists the upload before datareader runs, and the catch at :1058 never removes it. A rejected file stays in the file list and can be made current later, at which point MethodSelector renders normally over metrics that were never produced. One statement, above the chooser, naming the file and the actual number.
C is the check the audit was reaching for, in the right place. BaseAnalysisRunner.js:291–297 re‑validates against config.geneticCodeId, not the universal code datareader used. A file that uploaded cleanly can fail under vertebrate mitochondrial, where AGA/AGG are stops. That is the only pre‑run codon failure a user can still reach — and it is caused by a control on this screen, so it belongs beside that control, not in the method list.
It is already computable, cheaply. findStopCodons and formatStopCodonReport (fastaValidation.js:591–593) report alignment columns, and canonicalFasta is in the store. Run it on genetic-code change, not on every keystroke.
Hand C to audit item 1.2. Genetic code is that item's surface. Stating it here so the requirement is not lost is correct; building it inside the method chooser is scope creep. The chooser's obligation ends at panel B.
